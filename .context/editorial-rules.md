# Editorial Rules

Continuum exists for literary and philosophical writing, not for task
management. The interface should stay quiet, precise, and built around the text.

## Language And Voice

1. Default language is Spanish, with Rioplatense usage accepted.
2. Corrections must preserve the author's voice and rhythm.
3. AI correction is conservative by default: spelling, grammar, accents, and
   punctuation only unless the user explicitly requests rewriting.
4. Do not normalize away deliberate phrasing, repetition, or ambiguity unless
   the user asks.
5. Do not invent references, attributions, dates, or titles.

## What Counts As An Ocurrencia

1. An ocurrencia is a note-thought: it can be aphoristic, fragmentary,
   argumentative, or preparatory.
2. An ocurrencia may become a blog note, but it is valid as an unpublished
   draft.
3. Draft-first behavior is central. Writing in Continuum should not imply
   publishing.

## Typography And Format

1. Continuum's editor currently uses Newsreader Continuum for the writing
   surface. Reader typography decisions live in Diario and should be
   coordinated intentionally.
2. Literary numerals should use oldstyle numerals where the design calls for
   them, especially dates and aphorism numbers.
3. Visible dates use Spanish literary format, for example:
   `17 de Mayo de 2026`.
4. Machine dates remain ISO internally.
5. Quoted third-party text should use typographic quotation marks according to
   the current editorial convention.
6. References and superindices are structural editorial elements, not mere
   decoration.
7. Long quotes should feel integrated into the page, not like generic cards.

## Product Tone

1. The app should feel like a focused writing instrument.
2. Avoid dashboard language, onboarding copy, promotional language, and visible
   instructions inside the writing surface.
3. UI labels should be short and functional.
4. The Reader and Continuum should stay conceptually aligned, but visual fixes
   for the public Reader belong in Diario unless a Continuum authoring issue is
   explicitly in scope.

## Editing Behavior

1. Selecting text should preserve the user's ability to apply references,
   superindices, aphorisms, and corrections without losing context.
2. A tool panel must not steal the meaning of the current selection.
3. Empty-note behavior must be visually calm without storing fake content.
4. Right and left panels are tools around the text. They should not make the
   writing column jump or drift.
5. If a command cannot safely apply, the UI should say why in human language.

## Publication

1. Save and autosave create/update drafts.
2. Publish and unpublish are explicit actions.
3. Future publication from Continuum must use Diario's lifecycle authority.
